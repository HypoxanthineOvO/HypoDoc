# HypoDoc v0.2.0

Status: stable release candidate; publish only after local validation, remote CI,
and unsigned cross-platform package builds pass from the same source commit.

## Highlights

- Adds a renderer-owned SlideDeck projection with located diagnostics and immutable node sharing.
- Adds fixed 16:9 waterfall and presentation rendering across Web, Desktop, and VS Code preview.
- Adds Desktop workspace, import/export, settings, presentation navigation, and fullscreen workflows.
- Hardens Hypo-LaTeX profile/theme configuration, pinned Pandoc enforcement, resource containment,
  placeholder policy, and deterministic PDF builds.
- Restructures the public HypoDoc authoring Skill around canonical profiles, capability-aware themes,
  strict export evidence, and reproducible evals.
- Improves projection p95 by 99.3% and the complete slide pipeline by 71.2% against the recorded baseline.

## Version Mapping

- JavaScript workspace packages, Desktop, and VS Code extension: `0.2.0`.
- Python Hypo-LaTeX distribution: `0.2.0`.
- HypoDoc Spec remains independently versioned at `0.2.0-rc.1` with IR `hypodoc.ir/v1`.
- Product release tag: `v0.2.0`.

## Validation Required Before Publishing

- Run the full local validation suite from the stable candidate commit.
- Run all remote CI jobs from that same commit.
- Build unsigned Linux, Windows, and macOS installers and the VSIX from that commit.
- Verify artifact names, non-empty outputs, and SHA-256 checksums before creating the tag and Release.

## Known Limitations

- Installers are unsigned and macOS artifacts are not notarized, so operating-system warnings are expected.
- The macOS package produced by the current hosted runner is arm64 only.
- The VS Code extension is distributed as a VSIX and is not published to Marketplace.
- Folder workspaces do not yet watch external additions, removals, or changes.

`Docs/release/manifest.json` remains the historical v0.1.0 release manifest and is intentionally unchanged.
