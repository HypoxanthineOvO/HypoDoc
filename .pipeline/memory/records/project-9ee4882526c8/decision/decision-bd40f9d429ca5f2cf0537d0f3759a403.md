# 新产品 Git 历史策略

HypoDoc 新仓建立干净的产品提交历史，不把 Hypo-Markdown 或 Hypo-LaTeX 的旧 Git DAG 合并进 `main`。旧仓、来源 SHA、tag、dirty patch 与验证结果作为 provenance 和回退证据保留；筛选和修改后的内容按真实业务整合步骤直接提交到新仓。
